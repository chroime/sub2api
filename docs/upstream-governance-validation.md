## 验证边界

上述初次验证没有使用真实上游账号、生产数据库或生产配置。它证明本地实现、平台协议样例及并发/恢复逻辑通过验证，不代表所有 New API/Sub2API 定制部署都已实测连通。真实 WAF、用户权限、验证码、Passkey 和会话有效期仍按实际站点返回处理。后续获得用户授权的真实上游验证记录见下文。

目标分组元数据在预验证和本地适配器应用前各复核一次；此版本没有为整个目标分组设置实现覆盖所有配置字段的事务级 CAS。治理从不写目标分组的销售价。账号配置及其成员绑定则在数据库锁内进行原子校验和写入。

## 2026-09-26 原生接入、分组 Key 与批量映射补充验证

最终本地构建包含三字段接入表单、自动识别/登录/采集、账户概况、模型广场补充价格、独立分组 Key 管理和批量映射。管理员要求凭据直接展示明文：密码、验证码、会话令牌使用明文输入，已有 Key 在打开站点时自动完整显示并可复制。数据库存储加密与页面展示分开。

实际运行结果：

- 使用用户授权的真实上游，由治理中心表单提交用户名密码，原生 `/sites/:id/connect` 首先返回 CAPTCHA 挑战。
- 正常上游验证页面仅用于取得 Turnstile 证明，未在该页面填写或提交用户名密码。证明填回治理中心后，治理后端登录 HTTP 200，随后界面自动发起采集，HTTP 200。此验证不依赖导入管理会话令牌。
- 采集到 14 个可绑定分组及倍率，账户余额和冻结金额读取成功。渠道与模型广场能力均不可用，价格/模型条目为 0；界面明确显示缺失价格未知。
- 通过治理中心真实创建两个分组 Key，均返回完整值。重复创建返回 `reused`，对应上游 Key ID 保持不变。刷新站点后自动读取完整 Key，复制操作显示成功。
- 真实运行发现并修复原生密钥 DTO 的嵌套 `group` 对象与 New API 字符串差异。回归覆盖已有无关密钥、创建后列表、遮盖值的详情读取及重复复用。
- 全选 14 个分组，批量指定本地测试混合分组，生成并展示 14 项冻结预览；两个已有 Key 被识别为复用。此自动验证没有点击批量应用按钮，也未覆盖其他管理员正在进行的配置。

测试与构建：

- 治理后端、连接器、管理处理器、路由、中间件及本地账号适配器的定向测试通过。
- 两项真实 PostgreSQL 存储集成验证使用独立 schema，通过后清理；包含 AES 加密、未确定创建结果的恢复、所有权保护及原生嵌套分组形态。
- 前端治理与语言完整性共 **36 项测试通过**；类型检查与限定范围 ESLint 通过。
- `pnpm run build` 与 `go build -tags embed ./cmd/server` 通过。已重新启动本地嵌入式应用，健康检查 HTTP 200。
- 独立复核覆盖原生幂等请求头、批量超时/部分结果、复用登录后重试采集、跨平台价格同名、默认明文展示和过期异步结果丢弃，无未解决的功能性发现。
