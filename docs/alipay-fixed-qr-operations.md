# 支付宝定额收款码接入与核对

本功能使用预先在支付宝设置好金额的收款码。每个金额对应一个真实二维码，用户扫码后不必手动输入金额。本站负责展示匹配二维码、查询官方账务流水和处理到账核对。

## 配置入口

后台 → 系统设置 → 支付设置 → 独立的“支付宝定额收款码”卡片：

1. 新建停用配置；已有配置时选择需要编辑的那一项。
2. 填写名称、应用 ID、应用私钥、支付宝公钥，保持停用并保存草稿。独立卡片无需先开启支付总开关即可使用。
3. 保存后点击“测试账单连接”。仅测试查询权限时，收款 UID 和收款码规则可以暂时留空。
4. 在同一卡片补齐定额码、收款账户，并按需打开易支付兼容接口。原第三方易支付仍在“服务商管理”中配置。

本地入口：[内置易支付 · 支付宝定额码](http://127.0.0.1:8000/admin/settings#builtin-epay-settings)。其他部署使用对应站点域名加 `/admin/settings#builtin-epay-settings`。此入口需要已部署包含定额收款码功能的版本。

可以先填写应用 ID、应用私钥、支付宝公钥，保存为**停用草稿**，再点击“测试账单连接”。这一步只查询应用默认授权范围内的账务，不创建付款，不修改余额。连接成功表示接口可访问；不表示二维码的收款人或所有流水已经验证。

管理员选中已保存的配置时，“应用私钥”和“支付宝公钥”会自动回填完整内容，可直接查看和编辑。数据库继续加密存储，编辑器按选定实例读取这两个字段。易支付商户密钥仍按其独立的生成与复制流程管理。

正式收款前补齐：

- 收款账户 UID：2088 开头的 16 位支付宝账户标识。它与应用 ID 不同，用于指定查询账户和跨实例流水去重。
- 定额码规则：每条填写实际付款人民币金额、二维码链接（也可上传图片本地识别）、排序和启用状态。
- 应用需具备对应账单接口权限。如为代商户查询，填写所需的应用授权令牌。
- 服务端配置稳定的 `TOTP_ENCRYPTION_KEY`，用于加密保存新通道配置。密钥不可在升级或重启时随机更换。

准备正式收款时，开启支付总开关并保存，再在独立卡片启用已配置完整的实例，在“新支付宝订单来源”选择内置定额收款码。新订单使用新来源，旧订单仍由创建时的服务商处理。只保存草稿不会开启支付、启用类型或切换接单通道；只启用实例也不会隐式切换新订单到定额码。独立卡片保存不提交整页其他尚未保存的设置。

## 易支付兼容接口

独立卡片中的兼容接口使用单独的 PID 和签名密钥；PID 是该配置的实例 ID，签名密钥与支付宝应用私钥不同。当前支持二维码模式，下单返回真实收款码链接，调用方负责展示二维码。无需弹窗模式，也不提供 `submit.php` 托管支付页。接口的请求、响应、通知格式见 [易支付兼容对接文档](alipay-fixed-qr-epay-api.md)。

本站自身充值直接使用同一收款引擎；其他支持易支付的平台可以填写卡片显示的接口地址、PID 和签名密钥接入。兼容接口订单独立保存，不会在本网关产生一笔重复的本站余额充值。每笔官方收款在本站订单与兼容接口订单之间共同去重。

兼容接口付款确认后，查单立即可返回成功；签名通知由原有每 60 秒运行的通知任务发送和重试，失败后按已持久化的重试时间继续投递。快速账单采集不会把通知任务也改为每 5 秒运行。暂停新订单不会中断已确认订单的通知恢复。账户、金额或订单依据不足时仍需在“账单核对”中选择正确的订单来源、具体订单并填写依据。

## 金额规则

二维码规则按最终 `pay_amount` 精确匹配，金额按整数分比较。手续费、折扣及订阅汇率先计算，再匹配二维码；赠送额度不等于实付金额。

例如，选择充值 ¥100，手续费 1%，最终支付 ¥101，需要配置 ¥101 的收款码。仅有 ¥100 码时，该金额不能使用此通道。工程不擅自添加 ¥0.01 尾差，不给普通码链接附加未经验证的金额参数，也不选取最接近的金额。

收银台会将缺少对应二维码的档位置灰。其他付款方式不受定额码规则限制。同一提供商有重复启用金额规则时拒绝保存；不同实例可以各自维护规则，选单时只考虑支持该精确金额的实例。

## 查询与入账

官方接口为 `alipay.data.bill.accountlog.query`。查询使用 RSA2 签名和支付宝响应验签。接口权限、默认账户与定额码流水可见性，需要用真实应用及一笔既有收款验证。

后台“账单核对”可手动同步和查看流水。账单采集使用独立工作线程，避免其他支付服务商的慢查询阻塞确认：有近期未决定额码订单时，每 5 秒检查并采集正向流水；已确认或已取消订单在其金额窗口尚未被成功账单同步覆盖时，也继续快速补查。空闲时仍按每 60 秒的正常频率采集。单个工作线程串行执行快慢两种采集，并通过实例间互斥避免重复执行；5 秒是检查频率，不是到账时限。

正向游标按完整小时窗口推进，接近当前时间时重叠查询最近五分钟。正常采集另有独立持久化游标，分小时循环补查最近 24 小时；快速采集不重复执行整段历史补查。单次同步最多 45 秒，每个窗口最多 20 页，每页 1000 条；未完成窗口保留游标，查询错误不跳过账单。超过 31 天的断档不自动全量回补。当前查询批次的全部页和窗口持久化后，才开始匹配收款，避免先看到的一条流水抢先入账、漏掉同批次的另一笔同额收款。

新固定码订单使用 60 秒支付窗口，订单创建时同时持久化“收款账户＋实付金额”的独占记录。本站充值、订阅和外部易支付订单共用占用记录，即使配置为不同服务商实例，同一收款账户的同一金额也只能有一个付款窗口。不会自动增加尾差。

金额何时可再次使用，按订单状态判断：

| 订单情况 | 同金额再次下单的条件 |
|---|---|
| 本站或外部易支付订单已确认收款，有 `closed_at` | 无额外保护期；后续一次成功且足够新的账单同步覆盖 `closed_at`，并且已关闭窗口内没有尚未认领的额外收款后即可复用 |
| 历史预约已有收款认领记录，但没有 `closed_at` | 保守沿用原付款截止时间；同步覆盖该时间、无待核对额外收款后复用，无额外保护期 |
| 用户主动取消且写入主动取消标记的本站订单 | 取消事务提交后立即解除该订单的金额占用，无需等原付款期限、账单同步或额外隔离；不影响其他仍有效订单对同一金额的占用 |
| 管理员取消、旧版已取消且没有主动取消标记的本站预约 | 保留原 60 秒付款窗口；原截止时间到达、近期同步成功覆盖该时段且无待核对收款后即可复用，无额外保护期 |
| 有预约且尚未确认的订单 | 保留原付款窗口及截止后 30 秒保护期；近期成功账单同步必须覆盖保护期结束，窗口内无尚未认领收款后才可复用 |
| 未建立预约的旧版未确认订单 | 保留原付款窗口及截止后 120 秒隔离，并要求账单同步正常；不追溯建立自动匹配归属 |

30 秒是本平台为支付宝流水延迟可见预留的等待，不是官方接口规定的时长。已有预约即使记录了旧的 120 秒保护期，运行时也按“不晚于原付款截止后 30 秒”计算当前有效等待，不改写原始预约历史。账单同步失败或发现未处理收款时不会仅因倒计时结束就开放金额；不明归属或多笔收款需先核对。同步任务租约、同步新鲜度判断及后台迟到流水恢复范围使用各自的时间限制，不随这个保护期缩短。

迁移 285 为金额预约增加 `closed_at`。认领收款时，在同一数据库事务内写入 `closed_at = min(原 expires_at, 服务端认领时间向上取整到秒)`，作为金额归属窗口的排他结束时间。原 `expires_at`、订单截止时间和预约历史保持不变。这样既可在提前确认付款后释放金额，也保留确认所在完整秒的旧订单归属。同步游标必须成功、近期且已覆盖有效结束时间；仅任务启动或刷新更新时间不能释放金额。履约重试、通知重试及重启不会重新打开已关闭窗口。

迁移 286 增加 `user_cancelled_at`，在用户主动取消订单的同一金额锁及数据库事务中记录精确取消时刻。金额分配永久忽略带有该标记的预约；流水归属的有效结束时间为 `COALESCE(user_cancelled_at, closed_at, expires_at)`，原截止时间和历史保留。支付宝时间只有秒级精度，若取消后立即重下单形成同秒候选交叠，该秒的流水保留待核对，不猜测付款归属。超时处理使用 `EXPIRED`，不写入主动取消标记。管理员取消和旧版取消记录保留原释放条件。

相同金额普通占用返回 `ALIPAY_BILL_AMOUNT_BUSY`；已取消订单的原窗口尚未结束返回 `ALIPAY_BILL_CANCELLED_AMOUNT_WAIT`，附剩余秒数，不从取消或重试时重新计算等待。同步不满足释放条件返回 `ALIPAY_BILL_SYNC_REQUIRED`；已取消窗口有待核对收款返回 `ALIPAY_BILL_CANCELLED_PAYMENT_REVIEW`，此前未确认或已确认的窗口存在未认领收款时返回 `ALIPAY_BILL_PAYMENT_REVIEW`，均需先核对收款。

上述已取消订单等待与核对阻塞只适用于没有主动取消标记的预约。用户主动取消的旧订单即使存在迟到的待核对流水，也不会重新锁定金额；流水仍保留原订单的核对历史。主动取消成功页只显示“金额已释放，可以重新下单。请勿继续使用旧二维码付款。”；仅轮询发现取消状态时不承诺金额释放，提示查看订单记录核对。

优先使用官方商户订单号明确关联订单。没有平台订单引用时，仅新建且有金额占用记录的订单可自动匹配：付款发生在金额归属窗口内、收款账户和整数分金额一致、只有一个候选预约和一笔底层支付宝交易，且当前完整查询批次已持久化并覆盖收款发生的完整一秒。满足条件即可确认，不必等待原来的 60 秒付款窗口结束。判断使用支付宝付款时间；账单晚到但实际按时付款可恢复已过期订单。

收银台的 60 秒倒计时只表示允许付款的时段。到时隐藏二维码和支付入口；仍在核对时显示“账单核对中”以及剩余核对等待倒计时，终点固定为原付款截止后 30 秒，不因轮询、重新打开页面或恢复订单而重新计算。等待结束后显示“订单已超时”，停止转圈与页面轮询，并提供返回充值和订单记录入口；这不代表已经确认未付款或该金额在所有条件下都已释放。按时付款但账单晚到的订单仍可由后台恢复。确认收款后等待余额或订阅发放完成，再显示最终成功；本站充值余额会自动刷新。

另一用户对同一金额下单时，金额占用提示中的秒数表示当前保护期的预计剩余时间。原订单主动取消或确认收款后可以提前释放；保护期结束后仍需账单同步与收款核对满足条件，不应把秒数表述为新的付款时限或保证到点即可使用。

这是一种按金额占用规则进行的条件匹配。固定码不能远程失效，隔离期无法排除更晚付款或同账户其他来源的同金额来款；不能把金额和时间理解为已验证付款人身份。迟付、已取消订单、多笔候选收款或其他不满足条件的记录进入待核对。升级前历史订单不补建占用记录，也不会追溯按金额自动充值。

账务流水按收款账户和官方流水号去重；底层支付宝交易号还会单独认领，防止一笔交易的多个账务行重复充值。认领与订单转为已支付在同一数据库事务内提交。余额或订阅发放使用既有幂等履约；服务中断后可恢复已认领订单。

同一底层交易号在本站的普通支付宝确认与固定码认领之间也有互斥检查。若第三方回传的交易号不是官方支付宝交易号，或者另一个独立系统同时根据金额认领同一收款账户，本站不能自动替第三方做跨系统去重。切换时需要结清旧单或使用独立收款账户。

## 核对与故障处理

- 无有效金额占用记录且无明确订单引用、金额不符、实际超时付款、取消订单、收款账户不符或同窗口多笔交易等情况进入待核对。当前查询批次未完整持久化，或尚未覆盖付款发生的完整秒时继续等待；原 60 秒窗口尚未结束本身不再阻止确认。
- 过期二维码可能仍能收到款；本地取消订单不能使支付宝的固定码失效。
- 手动核对不能绕过金额、收款账户、已完成订单或交易唯一性约束。真实交易时间早于订单创建时不能认领给该新订单。
- 历史订单和流水存在时，不能删除服务商或改变其应用／收款账户身份。需要换收款人时新建实例。
- 无进行中订单时可以轮换私钥、公钥和授权令牌。旧实例仍需保留以支持历史核对。
- 固定码通道禁用自动退款和用户自助退款；本次未将固定码转账接入官方交易退款接口。

## 管理 API

以下接口都需要后台管理员身份：

| 方法与路径（前缀 `/api/v1/admin/payment`） | 作用 |
|---|---|
| `GET /providers/:id/bill-credentials` | 管理员编辑时读取该定额码实例的应用私钥和支付宝公钥，响应禁止缓存 |
| `POST /providers/:id/bill-test` | 只读测试最近 24 小时账单查询，返回条数与检查时间，不返回密钥或原始流水 |
| `POST /providers/:id/bill-sync` | 同步流水并执行明确关联的核对 |
| `GET /providers/:id/bill-receipts` | 按 `status`、`page`、`page_size` 查询精简核对记录 |
| `GET /providers/:id/epay-orders` | 查询当前配置的易支付兼容订单，支持分页、状态与订单号精确查询 |
| `POST /providers/:id/bill-receipts/:receiptId/claim` | 经人工验证后认领：本站订单 `{"order_id":123,"reason":"已核对付款凭证"}`；兼容接口订单 `{"epay_order_id":456,"reason":"已核对付款凭证"}`，两种目标必须且只能提供一种 |

## 上线验收

1. 用停用草稿测试查询权限，并确认一笔已发生的定额码收款可被读取。
2. 实际扫描每个拟启用的二维码，确认收款人、自动填写金额与规则一致。
3. 核对本站实际付款金额、到账额度和手续费。
4. 使用小额订单验证账单可见延迟、明确关联自动认领或人工核对流程。
5. 验证切换后新单走新来源，旧单继续核对，重复同步／确认不会重复入账。

自动化验证使用模拟签名响应、账单样本和隔离数据库，不代替上述真实收款验收。本次修复与文档更新未发起新的真实付款；既有订单或收款记录的检查不等于新支付验收。
