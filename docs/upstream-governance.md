# 上游治理中心

管理员菜单中的「上游治理」集中管理 Sub2API 和 New API 上游站点。它使用上游普通用户的权限发现分组、倍率、模型和可见价格，并将经管理员确认的分组映射导入本地账号池。

## 使用流程

1. 添加站点，填写 HTTPS 站点根地址、平台类型、采集间隔和可选代理。
2. 使用自己的上游用户名/密码授权，或提供该用户的管理会话令牌。支持的 TOTP 流程会继续请求验证码。密码仅用于本次登录。
3. 点击「立即采集」，查看上游分组及其声明倍率、用户覆盖倍率、实际倍率、峰值规则、模型、价格单位和渠道信息。
4. 勾选分组，明确选择 OpenAI、Anthropic 或 Gemini 推理协议，再选择兼容的本地分组。混合本地分组也可作为目标。
5. 生成导入预览，检查账户名称、目标分组、账户成本倍率，以及是否需要创建上游推理密钥。预览有效期为 15 分钟。
6. 点击「确认并应用此预览」。逐项显示结果；重试同一个预览会返回已有成功结果，或继续未完成项目。
7. 在绑定上选择文本模型，手动执行主动检查，或明确开启定时检查。

自动采集只产生快照和事件，不应用本地分组、账户成本或售价变更。管理员确认导入时，仅创建或修改该治理绑定拥有的本地账号及其分组；本地分组售价和渠道售价不受影响。

Sub2API 的用户覆盖倍率替换分组基础倍率。例如基础 2.0、用户覆盖 0.8，实际倍率是 0.8。New API 的用户分组倍率按上游已解析的值保存。账户成本采用现有数据库的四位小数精度，预览展示最终会保存的值。

## 授权与持久化

使用前配置稳定的 `TOTP_ENCRYPTION_KEY` 环境变量，或 `totp.encryption_key` 配置项。它必须是 32 字节密钥的 64 位十六进制字符串。治理功能复用现有 AES-256-GCM 加密实现；临时自动生成的加密密钥不能用于保存上游授权。

治理表中的管理会话和推理密钥均加密保存，并从管理 API 返回值中排除。登录请求正文不写入管理审计记录。普通导入账号仍使用工程现有的账号凭证存储机制，保持网关兼容。

数据库与加密密钥应一同纳入现有备份流程。修改或丢失加密密钥后，旧治理凭证不能解密。生产迁移使用新增的 `247_upstream_governance.sql`；按现有部署流程先备份数据库再升级。

站点必须是公网 HTTPS 根地址。管理请求禁止跟随重定向，固定访问对应平台的用户接口；使用已有的公网目的地址校验。选择代理后，代理不存在、失效或不可用会导致失败，不会切换成直连。

## 导入与重试

每个「站点、上游分组、推理协议」对应一个稳定标识。上游推理密钥使用该标识命名，本地账号通过内部标识关联。发现目录和生成预览不会创建密钥。

确认导入时，先查找或创建该分组的上游密钥，将其加密保存后再写本地账号。默认不添加额外的密钥配额或有效期，预览会明确说明；上游账户余额和站点本身的限制继续生效。

预览冻结站点版本、目录快照、本地目标分组和已有账号配置。配置变化时要求重新预览。账号写入和分组绑定采用事务，账号配置在数据库锁内再次校验，避免覆盖并发的管理员编辑。创建账号、绑定分组和调度通知在同一事务完成。

上游密钥创建没有统一的跨平台幂等 API。超时或响应丢失后不会在同次操作中盲目再次创建；下一次明确重试先按稳定名称核对上游密钥。不能把多平台远程操作作为一个数据库事务回滚，因此部分成功会保留并如实返回。

有导入绑定的站点不能直接删除。可关闭自动采集；删除治理元数据不会级联删除本地账号。

## 监控行为

| 项目 | 行为 |
| --- | --- |
| 目录采集 | 默认 15 分钟，可设 5–1440 分钟；站点可暂停 |
| 定时文本检查 | 默认关闭，开启时指定模型；默认 30 分钟，可设 15–1440 分钟 |
| 检查成功 | 必须返回有效文本，HTTP 200 本身不构成成功 |
| 检查结果 | 保存成功状态、耗时和经过归类的错误，不保存推理响应正文 |
| 事件 | 分组、模型、倍率、价格、渠道变化，以及采集失败、检查故障和恢复 |
| 自动处置 | 不暂停账号、不改变限流、不切换路由、不改本地价格 |
| 历史 | 每站保留最近 20 个目录快照、1000 条事件和 1000 条检查 |

工作器每分钟处理最多 20 个到期站点，每站每轮最多 5 个到期检查。每个服务进程最多同时执行两个远程治理操作，同站点操作使用 PostgreSQL advisory lock 在多个进程间互斥。工作器为单站发现设置 30 秒时限，每轮总时限 50 秒；开始网络操作前推进下一次计划时间，避免慢站点一直占据待处理队列。检查也先保留下一次计划时间，减少进程中断后立即重复计费的可能。

失败采集保留最近一次成功目录。故障和恢复按状态变化记录事件，不会每轮重复产生相同故障事件。打开页面、生成预览、保存监控配置本身不会发送推理请求；开启的检查在工作器运行到期任务时发送请求。

## 平台兼容性与范围

| 能力 | Sub2API | New API |
| --- | --- | --- |
| 普通密码登录 | 支持已验证接口 | 支持旧版 Cookie 和当前 Bearer 登录 |
| 密码传输加密 | 遵循平台 HTTPS 登录接口 | 支持已验证的 RSA-OAEP/SHA-256 格式，无明文降级 |
| TOTP | 支持临时令牌续接 | 支持当前 flow-token TOTP；旧版待验证 Cookie 流程需要交互授权 |
| 管理令牌 | 验证用户身份后使用 | 支持管理 PAT/会话令牌；旧版 PAT 需填写用户 ID |
| 分组与倍率 | 用户可见分组、覆盖倍率、峰值规则 | 用户可用分组及已解析倍率，auto 保留未知倍率 |
| 模型与价格 | 来自用户可见渠道接口 | 来自用户模型及 pricing 接口 |
| 渠道 | 上游暴露时保存 | 普通用户接口没有内部渠道清单，明确显示不可用 |

Sub2API 的 token 单价使用美元/Token；New API 的相对倍率保留为倍率，每请求价格保留美元/请求。缓存、区间、推理档位、图片/视频和表达式/插件价格作为结构化观察值保存，用于检测变化；不强行换算成一种本地售价。缺失的价格显示未知。

Passkey、需要浏览器交互的验证码和旧版 Cookie TOTP 不能由此版本完全自动完成，可使用明确提供的管理令牌。此版本不自动轮换刷新令牌；管理会话失效后显示需要重新授权。New API 加密密码支持的长度由 RSA 密钥决定，RSA-2048 的 OAEP/SHA-256 上限为 190 个 UTF-8 字节，尚不支持更长密码的 v2 混合加密格式。

接口兼容性基于当前工程和固定版本 New API 源码/本地协议测试；各站点的自定义接口、WAF、权限配置和部署版本仍需在实际连接时验证。

## 开发验证

治理核心、连接器、存储、管理 API、审计脱敏和账号适配器均有定向测试。PostgreSQL 测试只在显式设置隔离测试 DSN 时运行，使用独立 schema 并自行清理：

```powershell
# backend directory; only use a throwaway loopback database with governance_fixture user
$env:GOVERNANCE_STORE_TEST_DSN='postgresql://governance_fixture@127.0.0.1:55479/postgres?sslmode=disable'
go test ./internal/upstreamgovernance ./internal/repository ./internal/service ./internal/handler/admin ./internal/server/routes ./internal/server/middleware -run 'Governance|Connector|SQLStore' -count=1
```

前端验证使用 `pnpm exec vitest run src/views/admin/upstream-governance src/i18n/__tests__/localeKeyCompleteness.spec.ts`、`pnpm typecheck`、`pnpm lint:check` 和 `pnpm build`。本地浏览器验证使用独立数据库和虚构上游快照，覆盖预览无写入、确认导入、重复应用、监控开关和失败检查记录；不代表已连接真实上游。
