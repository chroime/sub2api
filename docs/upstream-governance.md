# 上游治理中心

管理员菜单中的「上游治理」集中管理 Sub2API 和 New API 上游站点。它使用上游普通用户的权限发现分组、倍率、模型和可见价格，并将经管理员确认的分组映射导入本地账号池。

## 使用流程

1. 点击「添加上游」，填写 HTTPS 站点根地址、上游用户名和密码。平台类型与名称自动识别；代理、名称和平台覆盖放在高级选项中。
2. 点击「登录并采集」。治理后端完成登录后立即采集；需要 TOTP 或验证码时停在继续验证状态。连接成功但采集失败时可以只重试采集。已创建的站点在同次接入重试中复用。
3. 查看账户可用余额、冻结金额、采集时间，以及可见分组、声明倍率、用户覆盖倍率、实际倍率、峰值规则、模型、价格单位和渠道信息。
4. 勾选或全选上游分组，批量指定一个或多个兼容的本地目标分组，也可逐项修改。每条映射最多选择 100 个目标，支持搜索、连续勾选和清空；同一上游分组与协议仍只对应一个本地账户、一个治理绑定和同一个 Key。上游声明的原生平台自动选中；已有绑定或 Key 优先沿用原协议，包含旧 Grok → OpenAI 记录。混合或未知平台由管理员明确选择，不会静默跳过。
5. 展开统一导入配置，按需选择模型模板、并发、账号优先级与配额。生成导入预览，检查账户名称、全部目标分组及各自售价倍率、账户成本倍率和完整导入配置，以及是否需要创建上游推理密钥。预览有效期为 15 分钟。
6. 点击「确认并应用此预览」。逐项显示结果；重试同一个预览会返回已有成功结果，或继续未完成项目。
7. 在「自动管理」中开启本站策略，后续成功采集会将符合规则的分组变化应用到已有治理账户；也可在概览的待处理变更中先预览、再批量应用。
8. 按站点配置余额邮件通知，并在绑定上选择文本模型、开启定时检查。充值预案可以保存和评估，本版本不执行支付。

界面先展示可搜索、筛选的站点总览，再进入单站的「概览、分组导入、自动管理、历史记录」。概览突出待处理变更和余额监控状态，完整 Key 在按需打开的弹框中明文显示。分组支持搜索、按协议筛选、只看已选和批量映射，价格与单组参数按需展开；切换页签保留当前导入选择和预览。推理协议筛选、逐组协议选择和目标本地分组的下拉选项及选中值均显示厂商图标。目标列表显示本地已启用分组，不兼容分组可见但不可选并注明原因；批量设置仍按每行协议校验，混合分组可接收所有支持的平台。尚未创建的本地厂商分组不会凭空出现在列表中。所有治理时间统一显示为 `2026-09-26 23:08:02` 的格式，使用浏览器系统时区，接口和数据库仍保存原始时间。

新站点和已有站点的自动管理均默认关闭。关闭时自动采集产生快照、事件和待处理变更；开启后，仅按本站策略维护已有治理账户的名称、成本倍率和调度状态。新增上游分组仍通过导入预览指定目标。完整导入仅创建或修改该治理绑定拥有的本地账号及其分组；本地分组售价和渠道售价不受影响。

批量选择不同厂商的目标时，逐行按推理协议分配兼容的目标集合，明确提示跳过的不兼容关联，保留全部已选上游分组。任何一行没有兼容目标时不能生成预览。重新导入已有绑定会将该账户的分组关联更新为预览确认的完整集合；新增目标不会额外创建账户或 Key。

也可在导入之前使用「创建分组 Key」：只为勾选分组创建或复用治理专用 Key，逐项显示结果。管理员点击「分组 Key」后读取并完整显示已有 Key，可直接复制或复制全部；创建新 Key 后也直接回显。关闭弹框时清空明文回显。此操作不创建本地账号、不要求先选择本地分组。后续导入复用这些 Key；重复点击不会刻意另建一套 Key。

Sub2API 的 `balance` 已是可用余额，冻结金额单独展示。New API 的 `quota`、`used_quota` 保留上游配额单位，不用假定的汇率转换成美元；缺失余额显示未知。

Sub2API 的用户覆盖倍率替换分组基础倍率。例如基础 2.0、用户覆盖 0.8，实际倍率是 0.8。New API 的用户分组倍率按上游已解析的值保存。账户成本采用现有数据库的四位小数精度，预览展示最终会保存的值。

## 授权与持久化

站点「编辑」弹框按站点信息、登录信息、采集设置分区，平台和代理使用统一下拉组件，代理列表较长时可搜索；在下拉中按 Esc 只收起菜单，再按一次关闭弹框。用户名和密码直接明文显示并可修改。保存站点资料和登录信息使用同一个版本校验及数据库写入，不调用上游登录，也不修改上游密码。仅修改普通站点资料时保留登录信息；显式清空用户名和密码可清除保存值。更换未绑定站点的地址或平台时清除原登录信息，新站点的凭证需要明确填写。

用户名和密码在密码登录成功后自动保存；TOTP 首步的凭证只暂存，匹配的验证成功后才成为可读取的登录资料。旧站点若只存有登录会话，会显示待补充的空字段；会话不能反推出原密码。读取失败或站点版本变化时阻止保存，可重新加载最新信息后重试。弹框关闭时清空其内存中的登录资料。

使用前配置稳定的 `TOTP_ENCRYPTION_KEY` 环境变量，或 `totp.encryption_key` 配置项。它必须是 32 字节密钥的 64 位十六进制字符串。治理功能复用现有 AES-256-GCM 加密实现；临时自动生成的加密密钥不能用于保存上游授权。

管理员治理界面中的密码、验证码令牌和会话令牌默认明文输入，托管 Key 弹框完整展示密钥。数据库中的管理会话和推理密钥仍加密保存；存储方式不影响管理员查看和复制完整值。普通元数据列表、快照和预览不返回密钥，管理员打开密钥弹框后通过专用读取接口取得完整值，读取和创建响应设置 `Cache-Control: no-store`。前端仅在当前组件内存保留回显，关闭弹框、切换站点或离开页面时清空。登录请求正文不写入管理审计记录。普通导入账号仍使用工程现有的账号凭证存储机制，保持网关兼容。

数据库与加密密钥应一同纳入现有备份流程。修改或丢失加密密钥后，旧治理凭证不能解密。治理基础迁移为 `247_upstream_governance.sql`，独立分组 Key 迁移为 `248_upstream_governance_keys.sql`，余额通知状态迁移为 `249_upstream_governance_balance_monitor.sql`，原生平台补全迁移为 `250_upstream_governance_platforms.sql`，站点登录资料迁移为 `251_upstream_governance_login_credentials.sql`。250 只扩展绑定及 Key 的平台约束，251 增加独立加密的登录资料字段，不改写已有会话、绑定和 Key。登录资料仅通过管理员专用接口读取，该接口设置 `Cache-Control: no-store`，站点列表不返回凭证，修改请求正文不记入审计日志；按现有部署流程先备份数据库再升级。

站点必须是公网 HTTPS 根地址。管理请求禁止跟随重定向，固定访问对应平台的用户接口；使用已有的公网目的地址校验。选择代理后，代理不存在、失效或不可用会导致失败，不会切换成直连。

## 导入与重试

统一导入配置默认如下，管理员可以在预览前调整：

| 设置 | 默认值 |
| --- | --- |
| 账号名称 | 上游根 URL + `--` + 四位小数精度的倍率（省略多余的零） |
| 备注 | 当前导入分组的完整 API Key，应用时写入 |
| 并发 | 5000 |
| 账号优先级 | 1，可手动调整；显式 0 仍有效 |
| 同步上游声明倍率 | 开启，同时开启现有计费信息探测 |
| 日 / 周 / 总配额 | 10000 / 700000 / 10000000 USD |
| API 长上下文计费 | OpenAI 协议默认开启 |

配额沿用原生账户的滚动 24 小时 / 7 天规则；已有账户的用量和无关配置会保留。上述默认值只在确认导入时应用，不在升级后追溯改写已有账户。未启用治理自动倍率同步时，声明倍率同步由原生 `/v1/sub2api/billing` 探测机制处理，依赖上游支持该接口。启用治理自动管理及倍率同步后，治理目录成为受管账户的倍率来源，可以持续应用 Sub2API 或 New API 目录提供的实际分组倍率，不再要求上游实现原生 billing 接口。

模型限制可以按 OpenAI、Anthropic、Gemini 协议保存命名模板，并为每种协议设置一个默认模板。模板共享保存在系统数据库中，刷新或重启后保留；并发编辑要求基于最新版本保存。模板保存的是具体模型的默认勾选列表。开启限制但没有选中模型时不能生成预览；关闭限制才表示不限制模型。预览冻结当时的模型映射，随后编辑模板不会改变已生成预览。

每个「站点、上游分组、推理协议」对应一个稳定标识。上游推理密钥使用该标识命名，本地账号通过内部标识关联。发现目录和生成预览不会创建密钥。

迁移 `252_upstream_governance_multiple_target_groups.sql` 为治理绑定增加 `local_group_ids`，从旧单组字段回填；已有账号的优先级和分组关系不变。请求兼容旧 `local_group_id`，新客户端提交 `local_group_ids`；同时提供时，旧 ID 必须包含在新集合中。预览冻结全部目标分组和账号优先级，未完成的旧格式预览需要重新生成，已经完成的预览仍可重放原结果。

确认导入时，先查找或创建该分组的上游密钥，将其加密保存后再写本地账号。默认不添加额外的密钥配额或有效期，预览会明确说明；上游账户余额和站点本身的限制继续生效。

预览冻结站点版本、目录快照、全部本地目标分组和已有账号配置。配置变化时要求重新预览。账号写入和分组绑定采用事务，账号配置及全部目标组的指纹在数据库锁内再次校验，避免覆盖并发的管理员编辑。创建账号、绑定完整分组集合和调度通知在同一事务完成；某个目标写入失败会回滚该次本地账户与关联写入。

上游密钥创建没有统一的跨平台幂等 API。超时或响应丢失后不会在同次操作中盲目再次创建；下一次明确重试先按稳定名称核对上游密钥。不能把多平台远程操作作为一个数据库事务回滚，因此部分成功会保留并如实返回。

Sub2API 创建请求带稳定的 `Idempotency-Key`，支持该接口的平台可在其幂等保留期内拒绝并发重复并回放已完成结果。New API 没有同等保证：如果上次超时请求仍在上游执行、密钥还未出现在列表中，再次明确创建仍可能产生同名密钥；不能声称所有平台都具备严格的一次创建保证。

仍关联未删除本地账号、存在待完成导入（账号 ID 为 0）或托管 Key 的站点不能直接删除；界面会明确提示站点仍在使用，可关闭自动采集并保留资源。如果只有已删除或已不存在本地账号遗留的绑定，删除站点会在同一事务内清理这些历史绑定及对应检查记录，再删除站点及其快照、预览和事件。删除过程不会修改本地账号，也不会撤销上游真实密钥。任何阻止删除的资源存在时，不会先清理部分历史绑定。

有导入绑定或托管 Key 的站点仍不能改成另一个上游地址，也不能改用另一个上游用户。

未绑定资源的站点更换地址时会保留已保存的自动管理和充值预案配置；重新连接前应核对这些策略。余额评估按新钱包身份重新计算，不沿用旧钱包的低余额事件。

## 监控行为

| 项目 | 行为 |
| --- | --- |
| 目录采集 | 默认 15 分钟，可设 5–1440 分钟；站点可暂停 |
| 定时文本检查 | 默认关闭，开启时指定模型；默认 30 分钟，可设 15–1440 分钟 |
| 检查成功 | 必须返回有效文本，HTTP 200 本身不构成成功 |
| 检查结果 | 保存成功状态、耗时和经过归类的错误，不保存推理响应正文 |
| 事件 | 分组、模型、倍率、价格、渠道变化，以及采集失败、检查故障和恢复 |
| 自动处置 | 默认关闭；明确开启后按策略维护已绑定账号的名称、成本倍率与调度状态 |
| 历史 | 每站保留最近 20 个目录快照、1000 条事件和 1000 条检查 |

工作器每分钟处理最多 20 个到期站点，每站每轮最多 5 个到期检查。每个服务进程最多同时执行两个远程治理操作，同站点操作使用 PostgreSQL advisory lock 在多个进程间互斥。工作器为单站发现设置 30 秒时限，每轮总时限 50 秒；开始网络操作前推进下一次计划时间，避免慢站点一直占据待处理队列。检查也先保留下一次计划时间，减少进程中断后立即重复计费的可能。

失败采集保留最近一次成功目录。故障和恢复按状态变化记录事件，不会每轮重复产生相同故障事件。打开页面、生成预览、保存监控配置本身不会发送推理请求；开启的检查在工作器运行到期任务时发送请求。

### 分组变化自动应用

自动管理面向已有治理绑定，不会把新发现的分组自动关联到任意本地分组。每站独立启用，默认同步成本倍率与模板名称、在分组消失后暂停调度、在分组恢复后恢复治理自身的暂停。默认连续确认 2 次、单次倍率上涨不超过 20%；可调整确认次数（2–10）和上涨阈值。保存策略仅保存配置，后续成功采集才执行；可先在概览查看变更并生成 15 分钟有效的冻结预览，每次选择 1–100 条应用。

| 上游或本地变化 | 本地处理 |
| --- | --- |
| 同一分组 ID 重命名 | 更新治理绑定的分组名称；账户名继续采用已约定的 `上游 URL--倍率` 模板，自定义账户名保留 |
| 实际倍率调整 | 同步账户成本倍率，按现有四位小数精度保存；倍率 0 有效 |
| 倍率上涨超过阈值，或从 0 上涨 | 列入待确认变更，自动任务不直接应用；管理员可预览并确认 |
| 分组消失 | 仅成功、完整、足够新的分组目录计数；不同快照至少间隔本站采集周期且不低于 5 分钟，达到确认次数后暂停账户调度 |
| 分组重新出现 | 仅恢复仍由治理持有的暂停；手工暂停、账户过期及其他不可用状态不会被强行恢复 |
| 本地 Key、上游地址、受管倍率或模板名称被手工改动 | 显示冲突，避免覆盖；明确重新导入可以建立新的管理基准 |

暂停使用 `schedulable=false`，保留账号、密钥和所有本地分组关联。后台维护仅写入本次变化涉及的名称、倍率、调度状态及治理元数据，保留模型限制、并发、账号优先级、配额及已用额度。New API 的分组名称本身作为 ID；改名会表现为旧组消失、新组出现，需要人工确认新组映射，不猜测继承关系。

治理接管倍率后，原生计费探测继续获取其他计费信息，但不能覆盖治理拥有的成本倍率，包括已经发出的探测请求。关闭自动管理或关闭倍率同步后，在下一次成功采集释放该来源标记，后续是否继续同步由账户原有的原生开关决定。关闭自动管理时手工应用目录倍率仍可使用，页面会提示原生同步可能继续更新倍率。

预览冻结站点、策略、快照和相关账户字段；变化过期或账户被并发修改时，应用会提示重新预览。原生账户写入、完成凭据和调度通知在同一数据库事务提交。若账号提交成功而治理结果写入失败，后续采集依据完成凭据恢复记录，避免重复改写。历史事件的「已确认」只是已读标记，不等于变更已应用。

### 余额邮件

在站点的「余额监控」中配置邮件通知。每个站点按共享钱包监控一次，避免同站多个分组重复告警。默认关闭；启用时设置余额阈值和通知间隔，默认阈值为 10 原生单位、间隔为 1440 分钟，可设置 15–10080 分钟。Sub2API 使用 USD，New API 使用 quota，单位不可混用。

收件人可为站点单独指定；留空时使用系统账户配额通知中已验证且启用的邮箱，若没有则使用第一位启用管理员的邮箱。发件服务器、账号和 From 完全复用系统邮件设置。

保存配置不发邮件，后续成功采集到的新余额小于或等于阈值时发信。余额未知或单位变化不会当成余额为零，也不会记录为恢复。每位收件人的发送间隔与失败状态单独持久化；失败至少 15 分钟后重试，已成功的收件人遵守各自冷却期。余额恢复只记录事件，反复跨越阈值仍保留通知间隔。邮件发送失败独立显示，不会把上游连接标为故障。

邮件中的采集时间也使用 `YYYY-MM-DD HH:mm:ss`，明确标注 UTC。SMTP 无法提供严格的一次投递保证：发送前保存预约，若发送后进程中断或状态写入失败，会保守等待完整通知间隔再重试。

余额检查跟随每站定时目录采集，在成功采集后判断；不是实时推送，也没有独立的高频余额轮询。治理工作器启动后运行，并每分钟扫描到期任务。诊断面板显示采集开关、间隔、最近尝试、最近有效余额观测、下次计划、数据新鲜度、邮件配置状态和收件人数。新鲜度以成功快照为准，失败尝试不会刷新有效时间；超过 `max(2 × 采集周期, 10 分钟)` 即为过期。过期、钱包身份不匹配、余额未知和单位变化不会触发低余额邮件或被认作余额恢复。

邮件就绪检查只读取系统 SMTP 与收件人配置，不会主动发信；配置就绪不等于已验证实际投递。未配置 SMTP、无有效收件人、发送失败会分别显示。前台诊断使用显式刷新及操作后更新，不会自动替换管理员当前冻结的预览；后台定时任务不依赖管理页面是否打开。

### 低余额充值预案

「自动管理」中的充值预案目前只支持关闭和本地评估。可保存原生余额阈值、充值金额、支付币种（USD/CNY）、每日预算和冷却时间；金额以整数最小货币单位持久化，余额单位与支付币种分开，New API 配额不会被假定为美元。

保存不执行评估；点击评估或后续成功采集会记录是否命中阈值、观察时间和阻止原因。同一次低余额事件复用持久化标识，恢复正常后再降到阈值会形成新事件；即使未开启邮件通知，也可单独启用预案评估。过期、未授权、停止采集、单位变化和预算不足会明确阻止。当前始终显示支付执行器未接入，不创建真实订单、不预留或扣减资金。

后端已预留支付能力探测、按幂等键提交及查询结果的提供方接口，但未注册任何实现。实际自动充值仍需对接上游支持的充值/支付接口及支付凭证，并实现订单账本、预算原子预留、冷却执行、回调/查询确认和不确定结果恢复。现有预案数据不充当支付账本，避免将评估结果误认为已充值。

迁移 `253_upstream_governance_automation.sql` 增加独立版本的自动管理策略、观察基准和变更预览；`254_upstream_governance_recharge_plans.sql` 增加充值策略与评估记录。升级不回填开启自动管理，不改变已有账号、分组关联和密钥；按照现有流程先备份数据库及加密密钥再升级。

## 平台兼容性与范围

治理导入、分组 Key、模型模板和主动检查支持工程现有的十种 API Key 账户平台：OpenAI、Anthropic、Gemini、Antigravity、Grok / xAI、Kimi、GLM / Zhipu、DeepSeek、MiniMax、OpenCode Go。`composite` 只作为本地混合分组类型，不创建同名账户平台。

New API 无 Sub2API 专有的 `/antigravity` 路由，因此列表中仍显示 Antigravity，但会禁用并说明原因；服务端同步校验。其余兼容 OpenAI 的厂商保留各自平台身份，通过上游站点的 Chat Completions 接口转发。新 CN/OpenCode 导入显式设置此协议，更新已有账户时保留管理员已配置的协议。

治理 API Key 账户以预览中的模型映射为准，不自动加入厂商默认模型或额外别名；空映射表示不限制上游模型。此规则随账户进入调度缓存，普通手工账户和 OAuth 的原有默认行为不变。页面必须成功读取已有绑定和 Key 元数据后才允许导入，后续重载失败也会关闭导入入口，重新选择站点可重试读取。

| 能力 | Sub2API | New API |
| --- | --- | --- |
| 普通密码登录 | 支持已验证接口 | 支持旧版 Cookie 和当前 Bearer 登录 |
| 密码传输加密 | 遵循平台 HTTPS 登录接口 | 支持已验证的 RSA-OAEP/SHA-256 格式，无明文降级 |
| TOTP | 支持临时令牌续接 | 支持当前 flow-token TOTP；旧版待验证 Cookie 流程需要交互授权 |
| 管理令牌 | 验证用户身份后使用 | 支持管理 PAT/会话令牌；旧版 PAT 需填写用户 ID |
| 分组与倍率 | 用户可见分组、覆盖倍率、峰值规则 | 用户可用分组及已解析倍率，auto 保留未知倍率 |
| 模型与价格 | 来自用户可见渠道和模型广场接口，严格按账号可绑定分组过滤 | 来自用户模型及 pricing 接口 |
| 账户概况 | 可用余额、冻结金额 | 剩余配额、已用配额，保留原生单位 |
| 分组 Key | 独立创建/复用、管理员显示/复制、导入复用 | 同左；遵循平台密钥回显接口 |
| 渠道 | 上游暴露时保存 | 普通用户接口没有内部渠道清单，明确显示不可用 |

Sub2API 的 token 单价使用美元/Token；New API 的相对倍率保留为倍率，每请求价格保留美元/请求。缓存、区间、推理档位、图片/视频和表达式/插件价格作为结构化观察值保存，用于检测变化；不强行换算成一种本地售价。缺失的价格显示未知。

模型广场单价仍需结合用户实际倍率；官方参考价独立保存，不能替代上游实收价。阶梯计费基准、分时倍率、图片独立倍率也保留。模型广场可展示尚未订阅的分组，因此治理只合并 `/groups/available` 已列出的分组；不会扩大账号的可导入权限。

普通密码登录默认只需地址、用户名和密码。Passkey、需要浏览器交互的验证码和旧版 Cookie TOTP 不能由此版本完全自动完成。外部站点的 Turnstile Site Key 受域名绑定，不能简单嵌入治理页面声称完成验证。此时界面明确显示待验证状态，提供续接字段和高级管理令牌方式；导入已有管理令牌不属于原生密码登录验证。此版本不自动轮换刷新令牌；管理会话失效后显示需要重新授权。New API 加密密码支持的长度由 RSA 密钥决定，RSA-2048 的 OAEP/SHA-256 上限为 190 个 UTF-8 字节，尚不支持更长密码的 v2 混合加密格式。

接口兼容性基于当前工程和固定版本 New API 源码/本地协议测试；各站点的自定义接口、WAF、权限配置和部署版本仍需在实际连接时验证。
