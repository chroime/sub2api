# 支付宝定额收款码：易支付兼容接入

接口基址为 `https://你的站点/api/v1/payment/epay`。后台“支付设置 → 支付宝定额收款码”独立卡片显示实际地址和 PID，并管理专用签名密钥、定额二维码和账单核对。当前提供**支付宝二维码模式**，无需用户手工输入金额。

## 配置客户端

| 配置项 | 填写内容 |
|---|---|
| 服务商 | 易支付／EasyPay 兼容 |
| API 基础地址 | 卡片中显示的完整基址，保留 `/api/v1/payment/epay` |
| PID | 卡片中该配置的实例 ID |
| Key／PKey | 专用易支付签名密钥；不是支付宝应用私钥 |
| 支付方式 | `alipay` |
| 支付模式 | `qrcode`，二维码模式 |

后台需要登记调用方通知地址所属的准确来源，例如 `https://shop.example.com`。来源不包含路径；通知地址可以是该来源下的 `/payment/notify` 等路径。正式环境使用 HTTPS。仅显式配置的 localhost／回环 IP 开发来源支持 HTTP。

收款码金额按订单实际付款人民币金额精确匹配。本网关不在商户传入的 `money` 上叠加手续费、折扣或尾差；调用方应先算出最终金额。没有对应金额二维码时，下单失败，不替换为相近金额。

## 下单

`POST {基址}/mapi.php`，Content-Type 为 `application/x-www-form-urlencoded`。响应为易支付顶层 JSON，不包含本站管理 API 的 `data` 外层。

| 参数 | 必填 | 说明 |
|---|---|---|
| `pid` | 是 | 商户标识 |
| `type` | 是 | 固定为 `alipay` |
| `out_trade_no` | 是 | 商户订单号，字母、数字、下划线或连字符，最多 128 字符 |
| `name` | 是 | 商品名，最多 256 字符 |
| `money` | 是 | 实付人民币金额，例如 `100.00`，最多两位小数 |
| `notify_url` | 是 | 支付成功通知地址；来源必须已登记，使用无查询参数的完整通知路径 |
| `return_url` | 否 | 来源需已登记。二维码模式不自动跳转此地址 |
| `clientip` | 否 | 客户端 IP，兼容参数 |
| `device` | 否 | 设备类型，兼容参数 |
| `param` | 否 | 回传值，最多 512 字符，不包含 `&`、`=` 或控制字符 |
| `sign` | 是 | MD5 签名 |
| `sign_type` | 是 | 固定 `MD5` |

签名方法：排除 `sign`、`sign_type` 和空值字段，将参数按键名字典序排列，使用解码后的原始值拼成 `a=v&b=v`，末尾直接追加专用签名密钥，计算小写 MD5。URL 编码在计算签名之后由 HTTP 客户端完成。

```python
import hashlib
import os
import requests

base = os.environ['EPAY_BASE'].rstrip('/')
key = os.environ['EPAY_KEY']
params = {
    'pid': os.environ['EPAY_PID'],
    'type': 'alipay',
    'out_trade_no': 'ORDER_20261111_001',
    'name': '订单付款',
    'money': '100.00',
    'notify_url': 'https://shop.example.com/payment/notify',
}
canonical = '&'.join(
    f'{k}={params[k]}' for k in sorted(params)
    if k not in ('sign', 'sign_type') and params[k] != ''
)
params['sign'] = hashlib.md5((canonical + key).encode('utf-8')).hexdigest()
params['sign_type'] = 'MD5'
result = requests.post(base + '/mapi.php', data=params, timeout=15).json()
if result.get('code') != 1:
    raise RuntimeError(result.get('msg', '下单失败'))
# 将 result['qrcode'] 编码成二维码展示给用户，保留 trade_no 供查询。
```

成功示例：

```json
{"code":1,"msg":"success","trade_no":"epay_…","payurl":"https://qr.alipay.com/…","qrcode":"https://qr.alipay.com/…","expires_at":"2026-11-11T02:01:00Z"}
```

`qrcode` 是二维码内容链接，不是已经生成好的二维码图片。同一 PID 下重复提交同一 `out_trade_no` 不会重复建单；若金额、名称、回传值或通知地址等发生变化，会返回冲突。已经关闭的订单应使用新的商户订单号重新下单，不能依靠重复请求延长旧码有效期。

新订单有效期为 60 秒，`expires_at` 是服务端的 RFC3339 截止时间。调用方应到时隐藏二维码并提示停止付款。该金额在同一收款账户下与本站订单、其他 PID 共享独占。尚未确认收款且有预约的订单保留截止后 30 秒保护期，并要求近期成功账单同步覆盖保护期终点、旧窗口中没有尚未认领收款；已确认收款的本站及外部订单无额外保护期，但需后续一次成功且足够新的账单同步覆盖关闭窗口，且窗口内没有未认领的额外收款，才允许同金额再次下单。30 秒是平台的账单可见性缓冲，不是支付宝接口硬性要求。

金额归属关闭时间由服务端在认领收款事务内持久化为 `closed_at = min(原 expires_at, 服务端认领时间向上取整到秒)`；接口返回的原 `expires_at` 与历史记录不改写。旧预约已有认领记录但没有 `closed_at` 时，保守使用原截止时间，无额外保护期。旧预约尚未确认时，即使保存的是 120 秒保护期，当前有效等待不晚于原截止后 30 秒，且原历史不改写。没有预约的旧版未确认订单继续保留原 120 秒隔离规则。

金额被占用或仍待核对时，下单返回 `code=-1`，不会替换为相近金额。客户端应继续查单以接收按时付款、账单延迟确认的结果，不能仅凭本地倒计时结束认定最终未付款；可展示“账单核对中”，停止前台等待后展示“付款待确认”并引导查看订单记录。

与外部订单共享金额的本站订单，若用户主动取消并写入主动取消标记，该订单立即解除金额占用，不必等原截止时间或账单同步；其他有效预约仍可占用同一金额。管理员取消或没有主动取消标记的旧版已取消预约，仍需等原 60 秒窗口结束、账单同步覆盖该窗口且无待核对收款后，才免除额外隔离。超时订单维持原隔离规则。本接口不提供取消订单操作。

## 查单

`GET` 或 `POST {基址}/api.php`。推荐 POST 表单：

```text
act=order
pid=你的PID
key=你的专用签名密钥
out_trade_no=ORDER_20261111_001
```

也可以使用 `trade_no` 查询。若同时提供两种订单号，它们必须指向同一订单。

```json
{"code":1,"msg":"success","pid":"123","trade_no":"epay_…","out_trade_no":"ORDER_20261111_001","type":"alipay","name":"订单付款","money":"100.00","status":0}
```

`status=1` 且 `trade_status=TRADE_SUCCESS` 表示已确认收款；`status=0` 表示尚未确认，不应据此发货或充值。服务端认领收款并持久化 `PAID` 后，查单立即可返回成功，无需等待原 60 秒付款期限或支付通知。暂停兼容接口或切换新单来源后，旧订单仍可按原身份查询。

## 支付成功通知

网关通过 GET 请求下单时冻结的 `notify_url`，携带 `pid`、`trade_no`、`out_trade_no`、`type=alipay`、`name`、`money`、`trade_status=TRADE_SUCCESS`、可选 `param`，以及 `sign`、`sign_type=MD5`。签名算法与下单相同。

调用方应验证签名、商户身份、订单号和精确金额，并主动查单确认后，按订单唯一键幂等完成业务，返回纯文本 `success`。通知会重复发送；同一订单不能重复加余额或发货。通知派发及重试仍由每 60 秒运行的原有任务处理，失败后遵循已持久化的重试时间；5 秒快速采集仅用于账单确认，不代表通知会在 5 秒内送达。成功确认收款不会因通知失败而回滚。

## 收款核对与支持范围

固定二维码通常不携带本站动态订单号。近期有未决定额码订单时，独立账单采集线程每 5 秒检查并查询正向流水；空闲仍每 60 秒采集，正常周期继续分小时补查最近 24 小时。当前查询批次的全部页和窗口必须先持久化，再进行匹配；5 秒是检查频率，不是确认时限。

新订单使用持久化的金额独占记录：付款时间位于金额归属窗口、收款账户和实付金额完全一致、只有一个候选预约和一笔底层支付宝交易，且完整查询已覆盖收款发生的完整一秒时，即可自动确认，不再等原 60 秒窗口结束。金额未被可靠占用的历史订单、迟付及歧义流水仍由管理员核对认领。固定码长期有效，因此无法通过金额和时间证明付款人身份，也无法彻底排除旧码晚付或其他来源的同额来款；本模式不能等同于官方动态订单号关联。只有确认收款后，查单才返回成功，网关才安排支付通知。

当前兼容下单、查询与支付通知；不支持微信、自动退款、`submit.php` 弹窗收银台或自定义渠道 `cid`。退款及未知动作返回 `code=-1`，不会假报成功。该文档描述功能协议，真实支付宝应用的接口权限和定额码收款可见性仍须通过后台连接测试与真实既有收款核验。
