# 按分组控制流式 ACK

在「分组管理 → 创建／编辑分组」中配置「流式首响 ACK」。当前所有平台分组均支持：OpenAI、Anthropic、Gemini、Antigravity、Grok、Kimi、智谱、DeepSeek、MiniMax、OpenCode Go，以及组合分组。简易模式也可管理其支持分组的 ACK，不改变该模式原有的其他功能限制。分组列表的 ACK 列显示开启、关闭或沿用账号。

系统设置「扩展功能」中的 ACK 总开关始终优先：关闭总开关时所有分组均不发送 ACK。开启总开关后，每个分组可独立开启或关闭，同一个账号可以在不同组应用不同策略。分组设置明确后，无需再开启账号上的旧 ACK 选项。

## 兼容现有配置

数据库字段 `groups.streaming_ack_enabled` 保存三种状态：

- `true`：该组开启，覆盖账号偏好。
- `false`：该组关闭，覆盖账号偏好。
- `NULL`：旧分组暂时沿用原来的账号设置。

迁移不自动开启或关闭任何已有分组。新建分组默认关闭；复制分组保留来源的三种状态。编辑旧分组时，只有明确选择开启或关闭才改变 ACK 策略，修改名称或倍率不会将兼容状态意外改为关闭。账号旧入口标记为兼容设置，供尚未选择的旧组使用。

创建和更新接口使用 `streaming_ack_enabled` 布尔字段。更新时字段缺省或 null 表示保持不变，不表示重置兼容状态。管理员返回字段保留 null，用户端分组 DTO 不暴露该管理选项。

## 请求行为

原有 SSE ACK 机制保持不变，只调整启用策略。普通非流式、WebSocket、实时语音、二进制响应不插入 SSE 确认帧；Gemini 原生流式接口要求 `alt=sse`。实际模型首字时间、独立 ACK 时间及计费处理不变。

原生网关按实际调度分组解析策略，包含 Claude Code 限制降级和无效请求回退。组合组按组合组自身的设置执行；切换目标厂商不会把设置改成另一个普通厂商组。强制平台路由继续保留请求组的策略。未发送 ACK 的重试会重新判断；已经发出的确认帧不能撤回，同一个响应仍最多发送一次 ACK。

分组开关不绕过账号归属、平台兼容性或影子账号限制。获取分组失败时不会据此开启 ACK。认证缓存同步保存三态字段并升级快照版本，分组更新沿用已有缓存失效流程。
