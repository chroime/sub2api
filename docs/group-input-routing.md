# 分组输入量路由

在管理员的「分组管理」中创建或编辑分组，可以设置「输入量路由」。配置默认为关闭，不影响已有分组。

每条规则先选择同步、流式或全部 HTTP 请求，再选择输入量条件：**全部**或 **Token 区间**。“全部”不限制输入 Token 长度；选择“Token 区间”时才显示起止输入框。切换条件时保留草稿中的区间值。

区间**包含起止值**：例如 `0–100` 包含 0 和 100，下一段可设为 `101–200`。规则按页面中的顺序检查，第一条同时满足请求类型和输入量条件的启用规则生效；“全部”规则与区间规则同样遵循这个顺序。

**没有任何规则匹配时，请求默认使用当前来源分组的原有调度。** 命中时只使用该规则指定账号与目标分组组成的候选范围。旧版本的“小于阈值”配置通过迁移转换为等价区间，例如 `< 200` 转为 `0–199`。已有区间规则默认保持“Token 区间”，新建规则默认选择“全部”。

指定账号和目标分组中的账号共同形成候选范围，选项不按来源分组的平台筛选，允许跨平台保存。每次请求只选择一个账号执行；相同账号重复出现时会去重。请求时按实际账号使用对应的转发协议，继续检查模型支持、账号并发、限流、配额、隐私、质量隔离及来源分组的利润控制。目标分组的规则不会再次执行。

「所有目标不可用时回退来源分组」默认关闭。关闭时，不会因粘性会话或既有模型优先规则调度到候选范围外；开启时，候选范围耗尽后允许使用来源分组原有账号。

路由不会修改用户的 API Key、来源分组、价格、倍率、订阅或账单归属。使用记录仍记录实际执行账号；服务日志中的 `group_input_routing_selected` 记录规则、来源分组、实际目标与是否回退。

## 输入量及协议范围

区间匹配使用本地 tokenizer 对请求中显式携带的消息、历史上下文、系统指令和工具定义进行预估，并不是上游最终返回的计费 Token 数。不会为此额外请求上游。

支持 HTTP OpenAI Chat Completions、Responses、Anthropic Messages 和 Gemini generateContent / streamGenerateContent。同步或流式取决于客户端请求模式，与上游内部转换使用的传输方式无关。

Messages 和 Chat Completions 可选择支持对应转换的 Anthropic、Gemini、Antigravity、OpenAI、Grok 及国产供应商账号。Responses 可使用 Anthropic、Antigravity 和 OpenAI 协议族账号；原生 Gemini 账号目前没有 Responses 转换器。Gemini 原生接口使用 Gemini 或 Antigravity 账号。TypeSafe/SystemOne 账号虽然可配置，但不会被发送不支持的文本协议。没有兼容可用目标时，按该规则的回退设置处理。

媒体输入、未知内容类型、服务端历史引用（如 previous_response_id、仅含 ID 的响应项）、缓存内容引用或加密上下文继续使用既有调度，不纳入本输入量规则的请求范围。“全部”只取消已支持 HTTP 文本请求的 Token 长度限制。WebSocket、Realtime 和异步后台请求也不纳入此 HTTP 规则。

流式响应已经返回模型内容后不会切换账号并拼接另一份回答。首内容前的可重试错误、连接保活、取消和超时仍遵循各协议现有的处理规则。
