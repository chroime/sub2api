# 上游治理中心模型监测

在管理员后台选择上游站点，打开「模型监测」。所有任务使用该上游分组已有的托管 Key，运行结果仅管理员可见，不进入生产调用日志或用户渠道状态。

## 手动检测

点击「新建检测」，选择分组 Key、模型、请求协议和思考等级。候选模型来自最新采集目录，也可以手工输入完整名称；目录可见不等于已经验证可调用。尚无 Key 时使用治理中心现有密钥管理流程，关闭后列表自动刷新。站点需要保持启用、登录身份有效，并已采集到与当前站点版本相符的分组目录。

支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Gemini，协议选项会按分组 Key 的厂商类型限制不兼容的选择。思考等级可勾选低、中、高中的一个或多个；已知不支持的模型与档位组合会跳过，未知兼容接口保留参数并显示未验证，不静默降档。当前配置要求至少选择一个思考等级，没有自动移除思考参数的运行模式。接口接受参数或回显模型名，均不能证明上游实际采用了相应推理强度或模型。

模板包含：

- 糖果逻辑题：用户原题，参考答案21颗（9圆形+12五角星形）。数值结论与证明复核分开记录。明确答案可识别，歧义回答待人工复核。
- 鹈鹕骑自行车：用户原提示词，保留原始回答与HTML；点击播放后在隔离iframe预览，也可下载原件。人工评价画面与动作，不修改模型作品。
- Token计数核对：指定输入构造长度，加入每次重新生成的头部/中部/尾部标记和输出回显，记录可见输入输出与usage差异。
- 上下文验证：检查指定输入长度下多个位置的信息召回；没有找到标记是复核线索，不能单凭一次失败确定上游截断。
- 轻量探活：回显本次随机校验码，固定返回OK不能通过。

可手动设置每个「模板×档位」的重复采样次数与批次并发数。总请求数等于「模板数×档位数×采样次数」，启动前显示。单批最多300次、采样次数1–100、并发1–32；整个部署的模型监测合计最多32并发，排队会在界面显示。同一目标的不同批次不重叠。连接池单独配置，避免原治理连接池的2连接限制影响并发测试。

界面的默认配置及范围如下：

| 设置 | 默认值 | 可填写范围或含义 |
| --- | --- | --- |
| 思考等级、模板 | 中；糖果逻辑题与 Token 计数核对 | 默认每批2次请求，可多选档位与模板 |
| 采样次数、批次并发 | 1、1 | 分别为1–100、1–32，所有组合总数不超过300 |
| 单次最大输出 | 4096 tokens | 1–65536，映射到所选协议的输出限制字段 |
| 输入构造目标 | 1024 tokens | Token 核对与上下文模板为64–500000；固定糖果、鹈鹕题干不受此值改写 |
| 总超时 | 180秒 | 1–1800秒 |
| 首段有效内容超时、流空闲超时 | 60秒、30秒 | 均为正整数秒，且不能超过总超时 |
| Tokenizer | 自动匹配 | 也可选 `o200k_base`、`cl100k_base` 或仅字符/字节统计 |
| Token 差异容差 | 10% | 0–100%，作为核对线索的阈值 |
| 策略间隔 | 1440分钟 | 正整数分钟；技术存储范围1–2147483647，不再使用原有业务上限 |
| 策略每日请求预算 | 100次 | 1–1000000，至少覆盖一轮请求总数，按 UTC 日期计算 |
| 连续失败告警阈值 | 3轮 | 1–100，按包含失败请求的已结束策略批次累计 |

输入值是构造目标，实际可见输入还包含题目说明和随机标记，其本地计数可能与目标不同。每次运行保存实际文本、所用 tokenizer 和实际计数，不将输入框中的数字当成已经验证的上游输入长度。响应读取另有8 MiB上限；超时、达到输出限制或响应过大时记录具体失败原因，已经收到的内容不能冒充完整回答。

提交具有幂等请求标识。取消批次会停止待执行请求并尝试中断执行中的请求；不重新发送结果未知的已发请求。可以查看每项完成状态、实际运行数量、首个有效文本时间和总耗时。低/中/高对比按同批次、同模板、同采样序号排列，鹈鹕作品可并列播放。

## 输入输出Token核对

每条记录保留原始请求正文（不包含鉴权头）、原始回答、upstream usage、SHA-256、UTF-8字节数和字符数。选择受支持的tokenizer后，对可见输入、输出独立计数；自动映射仅用于已知模型，未知型号可以明确选择o200k_base或cl100k_base，来源标记为管理员指定。未确定tokenizer时保留字节/字符证据，不伪造token数。

输入本地计数不包含未知服务端提示词及消息包装，使用「本地输入计数×配置比例」与32 tokens两者中的较大值作为核对余量。这是启发式阈值，不是服务端包装开销的已证上界。Anthropic缓存创建和读取与普通输入按已知口径合计；缺少必要字段时显示不可比较，Gemini不重复加入已经包含在输入里的缓存数。界面分别展示上游原始输入量、用于比较的声明输入合计和本地可见输入，避免混淆缓存口径。

OpenAI输出在提供明确reasoning_tokens时扣除隐藏推理再与可见输出比较。无法拆分隐藏推理时显示不可比较。缺失usage显示未知，非法数值单独标记。完整回显与标记召回另行展示，输入或输出异常不会被同一个模糊总分覆盖。

该能力用于发现和复查上游用量异常，不会改写上游账单，也不能证明不可见的服务端实际处理过程。本地计数即使精确对应所选 tokenizer，也不能证明上游内部使用了相同 tokenizer；管理员手工指定时同样如此。原始证据与口径保留，管理员可以对多次结果进行核查。

上下文模板一次检测一个输入构造目标，不会自动从4K递增到16K、32K或64K，也不推断模型最大上下文。需要比较多个长度时，分别配置并运行，按各自实际计数和召回结果判断。

## 定时管理和通知

配置可以保存为监测策略。新策略保存后默认关闭，启用后由独立后台任务执行，不依赖浏览器打开。间隔支持正整数分钟；后台约每15秒检查到期策略，约每秒派发排队任务。

策略每天的请求数预算按UTC日期计算。队列跨UTC日时也占用执行当天的额度；取消、跳过、不确定或已预约请求不会自动返还预留次数。并发、采样、单次输出额度、输入长度和超时共同限定每轮执行范围。这里的硬预算是策略请求次数，不宣称能在未知隐藏推理或价格口径下保证上游最终费用。

页面的「立即运行」创建独立手动批次，即使当前正在编辑某个策略，也不会自动归入该策略的每日预算或通知事件。手动批次受每批请求数、并发、输入输出额度和超时限制；持续自动管理需要保存并明确启用策略。

启用策略及其邮件开关后，可以使用系统SMTP发送失败、恢复、Token可疑差异和管理员确认的质量评价通知；收件人为空时沿用系统管理员通知解析。当前可用性告警按有失败请求的批次累计，达到设定轮数时形成事件；Token可疑差异或多位置召回失败形成单独的待核实事件。后续批次存在成功样本、没有失败和可疑差异时可形成恢复事件。界面展示投递失败状态，邮件失败约5分钟后重试，同一事件去重；取消、跳过、未知结果不冒充渠道失败。修改策略版本后清除旧基线，并停止投递旧版本事件。

质量通知使用当前策略版本下糖果或鹈鹕样本的人工「符合预期／不符合预期」评价，每个模板和档位采用最新已复核结果。未复核记录不记作失败；当前不会仅凭糖果数值错误、动画代码长度或一次延迟变化自动宣布能力退化，也没有按p95阈值自动发送延迟退化通知。鹈鹕各项视觉与动作评价通过复核备注记录，尚未拆成独立评分控件。

策略绑定原上游账号、站点地址、代理和托管Key身份，身份改变或分组消失时暂停或中止，原始结果仍保留。同目标的旧定时检查仍启用时，新策略启用请求需要显式携带接管选择。可以编辑暂停策略，勾选「本次启用时接管同目标旧文本检查」，再点击「保存并启用」；后端在同一事务中启用新策略并关闭旧检查。

列表中的普通「启用」不会自动接管。若启用遇到配置冲突，页面会重新读取策略并展开编辑，管理员核对分组Key与最新设置后，可明确选择接管并保存启用。接管是本次操作的一次性选择，不持久化为长期授权；普通「保存策略」不会把它保留给未来的启用操作。

## 历史与数据

历史详情按需加载原始作品、使用量与人工复核人/时间/版本。24小时、7天、30天趋势按完整请求配置、目标身份、模板版本和适配器版本分开统计，不跨档位拼接。至少5个成功且可比较的有效TTFT样本才显示p50/p95，非流式结果不伪造TTFT。每个窗口最多展示最近有结果的50组独立配置，超出时显示提示；24小时窗口按UTC小时聚合，7天和30天按UTC日期聚合，界面时间仍采用 `YYYY-MM-DD HH:mm:ss` 格式。

数据库迁移257新增独立策略、批次、运行、预算和通知表，不更改已有账户、分组或托管Key。删除策略保留历史，删除站点会级联删除该站点的检测记录；当前没有自动清理原始作品的保留期任务。

所有9个接口位于 `/api/v1/admin/upstream-governance/sites/:id/` 的 `model-policies`、`model-batches`、`model-runs`、`model-stats` 路径下，使用既有管理员鉴权与审计。普通用户和未登录用户直接访问也会被拒绝。

## 验证范围

开发验收使用本地HTTP与SMTP fixture验证请求适配、流解析、任务调度、通知和异常分支；浏览器验收使用内存路由fixture展示合成动画、token差异与进度。此类fixture结果只用于验证软件流程，不是任何真实上游的实测能力、延迟、token计量或邮件投递证明。确认某个真实渠道时，需由管理员选择对应托管Key发起明确的检测，并查看该次真实运行记录。
