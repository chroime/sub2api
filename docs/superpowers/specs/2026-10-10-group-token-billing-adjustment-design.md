# 分组 Token 计费倍率与缓存稳定性设计

## 目标

让分组中的下游输入/输出 Token 计费倍率在所有真实 API Key 认证路径上生效；让最小输入量规则、流式与非流式请求、预扣估算和认证缓存保持一致；让用户侧扣费使用配置后的计费用量，同时让管理员可以查看上游真实用量和真实上游成本。缓存命中或未命中不应因为缓存价格差异改变启用该功能的用户实际扣费。

## 已确认的根因

分组字段已经写入数据库，但 API Key 认证专用查询 `GetByKeyForAuth` 的显式分组投影没有选择三个倍率字段。认证缓存快照结构、快照生成和快照恢复也没有携带这些字段，导致生产扣费链路拿到零值，之后被归一化为 1 倍。现有 RecordUsage 实现还会原地修改上游 usage，使修正后的数量同时进入普通用户记录、管理员记录和上游成本统计。

## 设计

### 认证配置完整性

在 `GetByKeyForAuth` 的 `WithGroup(... Select(...))` 中增加输入倍率、输出倍率和最小输入量字段。在 `APIKeyAuthGroupSnapshot`、`snapshotFromAPIKey` 和 `snapshotToAPIKey` 中增加同名字段，并把认证快照版本从 27 提升到 28，以淘汰 Redis/L1 中不含新字段的旧快照。分组字段变化已有数据库触发器和应用级失效机制，版本升级负责覆盖滚动部署期间残留的旧缓存。

### 客户计费用量与上游实际用量分离

RecordUsage 不再原地修改 `ForwardResult.Usage` 或 `OpenAIForwardResult.Usage`。每条记录保留上游返回的原始非缓存输入、输出和缓存分类；另计算一份只用于客户扣费、API Key 配额、订阅扣费和用量排行榜的计费用量。UsageLog 增加管理员专用的原始输入/输出字段，普通用户 DTO 不暴露这些字段，管理员 DTO 返回原始用量。现有 `input_tokens`/`output_tokens` 保持用户侧的计费用量展示，因此普通用户看不到“修正”标记；账号统计成本和管理员的上游成本使用原始 token 与上游缓存价格。

### 缓存中性的客户输入计费

对启用了非 1 输入/输出倍率的分组，在达到最小输入量后，把逻辑输入定义为：非缓存输入 + 缓存读取 + 缓存写入。客户输入计费使用匹配价格档的普通输入单价乘逻辑输入量和输入倍率，不使用缓存读取/写入的折扣单价；客户输出计费使用输出单价乘输出倍率。这样同一逻辑请求从未命中变为命中，客户实际扣费不因缓存分类变化而下降。上游实际成本仍按原始缓存读写分类和各自单价计算，因此缓存命中率提升仍能降低平台成本。

最小输入量按扣除缓存读写后的原始非缓存输入 Token 判断。低于阈值时不应用输入/输出倍率，探针和按次/按量的图片、视频、音频计费不进入该逻辑。OpenAI 聚合输入先拆出缓存读写，再按同一规则处理；Anthropic/通用网关直接使用独立的非缓存输入字段。

### 缓存命中率稳定性

计费逻辑不修改上游请求体、缓存键或会话路由。继续使用现有的 session/previous-response 粘性选择，保持会话在同一上游账号，保留请求中的缓存标识和 TTL 策略。新增回归断言保证：计费倍率只改变客户扣费输入，不改变 `ForwardResult` 中的缓存分类，也不改变缓存 TTL 覆盖结果。缓存率达到 90% 以上仍依赖会话标识稳定、提示词前缀稳定、同一模型/账号和有效 TTL；代码不会用扣费字段伪造缓存率。

### 预扣估算

余额预扣的 token 估算使用同一个分组计费用量转换：估算输入达到阈值时应用输入倍率和逻辑输入规则，估算输出应用输出倍率；图片、视频、音频按次/按量估算继续走原有路径。这样预扣金额不会低于最终结算金额，避免倍率大于 1 时并发预留不足。

## 测试策略

- 纯函数：倍率、阈值、缓存中性逻辑、负数/零值归一化。
- 认证投影：真实认证查询返回三个分组字段。
- 认证缓存：快照 JSON 往返保留三个字段，旧版本快照被淘汰。
- 通用网关和 OpenAI 网关：200/50 在 2x/3x 下客户计费用量为 400/150，原始用量仍为 200/50；99 输入低于阈值时保持原始客户计费；缓存读写变化不改变客户输入扣费；流式和非流式一致。
- 账号统计：`AccountStatsCost` 和管理员原始用量使用上游真实 token；普通用户 DTO 不含原始字段。
- 图片、视频、音频和探针不套用 Token 倍率。
- 预扣估算与最终结算使用同一倍率规则。
