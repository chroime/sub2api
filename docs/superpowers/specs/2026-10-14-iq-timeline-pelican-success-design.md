# 智商监测 24 小时鹈鹕时间线成功优先

## 背景

用户侧“智商监测”页面将本地鹈鹕监测结果按 30 分钟时间桶展示为绿色、红色或黄色。当前后端在同一时间桶同时存在成功和失败记录时，让失败状态优先，因此一次成功生成作品也可能仍显示为红色。这与“只要能成功生成鹈鹕作品即为绿色”的产品规则不一致。

## 目标与范围

- 在 24 小时检测时间线中，只要某个 30 分钟桶内存在成功的本地鹈鹕检测，就返回 `pass`，由现有前端显示绿色。
- 当桶内没有成功记录但存在失败或不确定记录时，返回 `fail`，由现有前端显示红色。
- 当桶内没有任何本地鹈鹕记录时，继续返回 `empty`，由现有前端显示黄色。
- 继续限制为公开可见的本地分组鹈鹕检测；隐藏记录、非鹈鹕模板和上游监测不参与时间线。
- 保持 API 字段、前端布局、作品列表和管理员审核行为不变。

## 设计

后端在 `model_public.go` 的时间线 SQL 聚合中使用明确的质量排序：成功为最高级别，失败或不确定为次级别，无记录为零级别。Go 映射层将最高级别转换为 `pass`，次级别转换为 `fail`，零级别转换为 `empty`。这样同一时间桶的聚合遵循 `success > failure > empty`，不需要前端根据分页后的作品列表重新推断状态。

“成功生成鹈鹕作品”沿用现有监测记录的成功定义：记录状态为 `succeeded`、模板为 `pelican`，并且属于 `local_group` 目标。作品 HTML 的脱敏和大小限制仍由作品列表查询负责，不改变时间线的公开投影边界。

## 错误处理与兼容性

- `failed` 和 `indeterminate` 继续归入失败级别。
- 成功和失败在同一桶共存时，成功级别覆盖失败级别。
- 前端继续使用已有的 `pass`、`fail`、`empty` 状态映射，不新增状态值或翻译键。
- 现有时间窗口、30 分钟桶边界和公开可见过滤条件保持不变。

## 验证

- 更新后端时间线单元测试，验证同一桶内成功和失败同时存在时结果为 `pass`。
- 保留并验证无成功但有失败时结果为 `fail`，无记录时结果为 `empty`。
- 运行 `backend/internal/upstreamgovernance` 相关 Go 测试。
- 运行前端 IQ 检测相关测试，确认 `pass` 仍渲染为绿色且没有接口或布局回归。
- 启动本地服务后通过用户侧智商监测接口和页面检查实际时间线颜色。

## 不在本次范围内

- 不修改鹈鹕模型请求、输出上限、作品提取或管理员审核逻辑。
- 不改变日额度、检测调度或数据库表结构。
