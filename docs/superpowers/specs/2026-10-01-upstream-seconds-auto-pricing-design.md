# 秒级上游观察、分组自动调价与亏损保护

状态：已确认，进入实现。当前文档记录已确认的规则；运行中的采集频率、售价和邮件策略将在实现完成并验收后启用。

工作分支：`codex/upstream-governance`；调查基线：`7915c3a55`。

## 目标

管理员可以按秒配置上游观察频率。系统发现已绑定上游分组的倍率变化后，自动计算本地分组的对客倍率，并在异常、调价成功或保护介入时发送邮件。一个本地分组关联多个上游时，按统一规则计算一次，避免不同站点轮流覆盖售价。

默认推荐保持启用时已有的利润空间，并复用分组已有的最低毛利率与安全缓冲作为底线。毛利率指 `(售价 - 成本) / 售价`，与成本加价百分比不同。策略启用前展示当前成本来源、售价、计算后的倍率和受影响范围；存量分组不因升级而自动改价。

轮询只能缩短发现延迟，不能保证上游变化发生时立即知道。已发送到上游的请求不能撤回；账单级收益还取决于价格口径、用户折扣、订阅收入及上游实际计费。

## 采集与观察

### 两种周期，各自按秒配置

1. 快速观察：完整可见分组、稳定ID、名称、基础倍率、用户覆盖倍率及峰时规则。新策略建议10秒，可输入1、5、15、30等任意受存储表示支持的正整数秒。
2. 完整采集：余额、完整模型和价格目录、渠道等。保留当前频率，界面支持秒/分单位切换；不自动继承快速观察周期。

Sub2API优先复用分组和用户倍率接口；New API复用用户可用分组接口。已保存会话的续期继续独立调度，避免每秒执行登录或批量续期。密钥库存与模型推理测试保持独立周期。

调度按实际到期时间派发，使用有限并发的公平任务池、已有跨实例站点锁和持久化到期预留。同站同一时刻最多一个远端任务，慢站不串行阻塞其他站；上一轮未完成时合并后续到期请求，不补发积压请求。界面显示设置周期、实际成功观察时间、耗时、下次运行、排队或退避原因。

429遵守可识别的Retry-After并持久化退避；网络失败采用有上限的退避。成功后恢复用户周期。间隔代表目标频率，网络耗时和上游限流会影响实际频率。

### 兼容与数据新鲜度

秒字段采用BIGINT/int64，存量分钟值精确乘60。历史最大值2147483647分钟对应128849018820秒，不能落到INTEGER秒字段。兼容旧API的分钟输入；两种单位同时提交时必须一致，不能默默截断。存量站点不自动加速。

快速观察维护独立的成功时间、完整性、来源身份和结构修订号。目录内容不变只更新观察时间；余额变化不改变分组结构修订。导入及密钥操作只在相关目录、绑定或配置确实变化时失效。不能每秒写一个全量快照并将有效历史缩短为20秒。

首次成功观察只建立基线，不群发“新增全部分组”。身份不符、401/403/429、超时、解析失败、分页不完整都表示失败或未知，不能推断为删除、免费或余额恢复，也不能推进最后成功观察时间。删除仍须完整列表上的连续确认；新增分组通知管理员，不擅自创建本地映射。

## 本地分组定价规则

### 策略属于本地分组

每个本地计费分组只有一份带版本号的调价策略。站点页面显示该站点涉及的本地分组策略，但不会为每个上游各存一份会相互覆盖的售价规则。一个上游账户关联多个本地分组时，每个本地分组独立计算。

纳入成本候选的来源必须是该计费分组实际可路由到的账户，包含配置中的备用来源。不能仅按当前被选中或最低优先级账户决定售价。混合分组按真实计费父分组处理；解析不完整的路由关系显示无法自动定价并进入保护状态，不直接改成员组倍率冒充父分组售价已经变化。

默认取所有可比来源的最高成本作为定价基准，避免低价来源故障后切到高价来源亏损。临时暂停、限流或观察失败不能自行移除高成本来源并触发降价；来源永久移除要有明确配置或已确认的目录变化。需要更低售价的运营者可将昂贵备用来源拆到另一分组。

### 推荐默认：保持当前利润空间，叠加最低毛利底线

首次启用时冻结有效成本基准C0与有效售价P0，保存系数K=P0/C0。之后以最新成本基准C计算：

`目标有效售价 = max(C × K, C / (1 - 最低毛利率 - 安全缓冲))`

最低毛利率、安全缓冲沿用本地分组现有配置，可在调价策略中明确修改；两者均不得小于0且总和必须小于1。没有配置时不擅自填入20%或其他收益目标。需要完全按目标毛利运营时，可切换为“目标毛利模式”，仅使用公式的第二项。

示例：在相同模型计费基准下，上游成本0.20、本地售价0.30，K=1.5，毛利率约33.33%。上游成本变为0.22后，目标售价为0.33；成本回落至0.18后，目标为0.27。四位小数落库时向上取整，避免舍入跌破底线。计算始终基于冻结锚点，不能用上次经过舍入的价格反复连乘。

C0=0、当前免费售价、未知成本、不同币种或未知计价单位都不能套用除法；启用预览需明确提示，先选择可验证的成本/目标毛利规则。New API的`auto`或未知单位不能按0或美元处理。

### 上涨、下降及人工修改

- 正常上涨：获得完整可信的新观察后立即重算，无需等待完整目录周期或邮件发送。
- 正常下降：成本降低持续60秒后再调低售价，期间有反弹则重新计算；稳定时间可配置。
- 异常涨幅：沿用已设置的涨幅审核上限作为初始规则，允许单独设置或关闭。超限时保存最新成本事实，阻止受影响来源继续按旧价接新请求，并通知管理员；不能只保留旧成本等待审核。
- 人工编辑：策略持有最后一次自动写入的倍率和配置版本。管理员改价或改绑定后进入冲突待核对，不覆盖人工值。重新确认锚点后恢复托管。
- 关闭策略：停止后续自动改价，保留当前售价和审计记录；不恢复成过时的启用前价格。

## 亏损保护与调价生效

将“发现的真实成本”与“是否允许自动调整售价”分开保存。成本上升已经可信时，即使售价需要审批、数据库写入失败或缓存尚未更新，风险判断也必须使用新成本或暂停受影响来源。保护按来源与计费分组处理，尽量继续使用仍符合利润要求的其他来源。

正常路径为：持久化可信观察 → 标记受影响定价范围正在核对 → 计算最新成本与售价 → 在事务内校验策略、绑定和人工编辑版本并提交 → 更新调度、认证和用户倍率解析缓存 → 解除本次保护 → 异步通知。跨站事件触发同一本地分组时必须串行归并，以最新有效观察统一计算，不能最后完成的站点覆盖其他来源。

现有利润门的比较式是 `账户成本 <= 用户实际售价 × (1 - 最低毛利率 - 安全缓冲)`。保留该规则，并对启用本策略的范围增加最新成本、定价修订和观察过期检查。配置/缓存读取失败时，该范围必须保持保护或回源核验；不能沿用旧有fail-open后仍宣称防亏。

用户倍率解析缓存应缓存“是否存在个人覆盖及覆盖值”，默认值取当前请求的分组价格快照，避免把旧分组默认值缓存30秒。自动调价还需带版本的跨实例失效通知及失败恢复，调价中状态不能在缓存传播尚未就绪时提前解除。

原有用户专属倍率不自动改写，利润门按该用户实际收费检查。某些专属低价用户可能在上游涨价后无法使用高成本来源，启用预览和告警需列明影响。请求一旦开始，保留请求级价格快照，不中途上调用户收费；尚未发往上游的重试应重新检查最新成本。已发送请求的风险不能通过改库追回。

## 价格口径与范围

自动倍率跟随先覆盖工程已有利润门支持的OpenAI、Anthropic、Gemini、Grok及Antigravity文本Token计费路径；其他平台必须经过入口和最终发出请求前的覆盖测试，才能标记为受保护。成本与售价的倍率只有在模型、输入/输出、缓存、长上下文和计价单位基准可比时，才可解释为毛利。基价不同但能完整归一化的场景，以同一计价维度的保守等效成本评估；无法归一化的模型显示“成本口径未确认”并阻止其按已保证利润的规则自动放行，不能编造换算结果。计价兼容性变化本身也触发重新核对，不能只监听倍率数字。

上游`ResolvedRateMultiplier`目前只解析个人覆盖或基础倍率，峰时字段单独保存，并非当前峰值成本。峰时生效需知道上游时区与规则；接口未提供时区时必须显式配置。计算采用上游当时有效成本及本地实际售价，换算回本地基础倍率时避免再乘一次本地峰值因子。峰值边界需要独立触发重算，不能等到倍率数字变化。

独立图片、视频、实时音频、按次工具费及固定价套餐收入不能用文本倍率保证毛利。OpenAI Fast等由平台承担服务等级价差的优惠也需要纳入实际成本核对。本次应在界面明确这些覆盖边界，不自动改写它们的独立价格。订阅组倍率影响额度消耗，不等价于改变套餐现金收入，因此展示“额度/成本口径保护”，不宣称套餐整体毛利已经被保证。

## 邮件与运维界面

复用系统SMTP发件设置。变化订阅有独立开关和收件人；可以沿用站点已有通知收件人，不依赖低余额开关。分组新增/删除/改名、上游倍率变化、自动调价成功、调价失败、保护启停都进入变更历史。

涨价、暂停或失去成本观测时立即入队；普通下降、重命名等同轮变化汇总。通知包含站点与上游分组、变化前后成本、本地分组新旧倍率、实际执行结果、受影响账户/用户范围和时间。API Key、密码和登录令牌不需要进入邮件。

使用持久化通知队列，按事件修订、策略版本及收件人去重。投递不占站点网络锁，不阻塞自动调价；失败退避重试，重启后继续。同一次事件反复观察不能重复生成邮件；SMTP在投递成功但确认丢失时可能重复，因此不能宣称外部投递严格一次。

当前“自动管理”页增加三个清晰分区：

1. 观察频率：快速观察、完整采集、最近成功、实际耗时和退避原因。
2. 分组自动调价：本地分组、全部成本来源、当前有效成本、当前售价、目标售价、毛利底线、托管状态、启用预览。
3. 变更通知：事件订阅、收件人、SMTP就绪状态、最近发送结果。

历史页连起“上游变化→本地调价→保护动作→邮件结果”，不用到多个页面猜测是否真正应用。

## 持久化与测试验收

新增秒级间隔/到期时间、快速观察及结构修订、本地分组唯一调价策略、定价操作/保护状态、通知队列。使用新迁移，不修改已应用的247—260迁移；升级前按现有流程备份数据库、程序、配置及加密密钥。

必须验证：

- 1秒、5秒及极大历史间隔，单位兼容无损；慢站不阻塞快站，无同站重复远端请求，多实例到期争抢只执行一次。
- 无变化的高频观察不使预览过期，真实相关变更会使旧预览失效；首次基线无邮件风暴。
- 429退避、授权失败、部分分组列表、未知倍率及异常价格不会被当成降价或删除。
- 单上游上涨、稳定降价、多个上游先后更新、昂贵来源暂时故障、真实备用路由与一个账户多组，均按同一规则计算。
- 目标毛利与加价比例区别、四位小数向上取整、0成本、峰值切换、不同基价与币种、用户覆盖和套餐边界。
- 大幅上涨待审批时不继续使用旧成本放行；定价提交失败、缓存滞后、进程中断与人工改价不会导致未受保护的旧价流量。
- 调价后新请求使用新倍率，进行中请求不被追溯涨价；重启恢复操作不重复加价或重复创建变更事件。
- 通知失败不回滚售价、不阻塞采集；重复观察不重复入队，重启可继续投递。

开发使用合成上游与隔离数据库。实际策略启用前生成影响预览；本轮设计阶段不更改现有售价或发送测试邮件。

## 待确认的业务规则

推荐：保持当前利润空间并叠加已有毛利底线；多个来源取最高可比成本；上涨立即跟随、下降稳定60秒再跟随；异常超限或成本无法确认时先保护受影响来源再邮件通知。周期、下降稳定时间、审核上限均可配置。确认这组默认规则后进入实现，避免实现过程中再逐项打断。
