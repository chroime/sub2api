# 低余额预扣费：故障恢复与容量管理

本页说明预扣费、用量记录持久补写与运维日志的运行边界。业务开关、阈值和固定预扣金额仍在系统设置的「扩展功能」中管理，分组覆盖规则不变。

## 请求、冻结和故障恢复

一次请求预扣成功时，数据库同时保存随机所有者标识和两分钟租约。请求及其保留的计费任务存活期间，每30秒续租一次；客户端断开不直接终止后台计费任务的所有权。任务明确结束后写入结束标记，不能重新续租。

维护任务默认每30秒检查一次，每批最多500条。进程异常退出后，过期租约会生成待核对记录，**不会仅凭时间长就自动退回冻结金额**。旧版本没有所有者标识的遗留冻结在迁移后有15分钟宽限期。若数据库短暂故障时请求仍在执行，同一所有者可以恢复心跳；有效租约期间管理员不能人工处理该笔款项。

正常请求按原逻辑计算真实费用并结算；没有产生账单的正常终态释放余额。真正的扣费或退款处理失败、所有者失联等情况进入核对。管理员处理前应核实上游账单；「租约过期」表示缺少存活证据，不保证上游没有继续执行或没有产生费用。

```yaml
billing_maintenance:
  interval_seconds: 30   # 5–3600秒
  batch_size: 500        # 1–1000条
  hot_retention_days: 90 # 7–3650天
```

部署配置修改后需重启。参数越界会在启动校验时报告，不会静默采用错误的频率或批量。

## 已扣费但缺少使用记录

新的计费事务会同时保存经过字段白名单处理的用量快照到 `usage_log_outbox`。扣款、去重标记、预扣结算和快照一起提交或回滚。快照不包含完整请求体、模型输出或带凭证的用户/API Key/上游账号关系对象。

正常使用记录持久化成功后，核对请求、Key、用户、账号、实际费用和总费用，再删除对应补写任务。仅进入内存队列不能作为完成依据。

后台每10秒领取至多128条任务，8个并行处理，领取及单条处理各限时5秒。失败按持久退避重试，最长重试间隔1小时；多实例通过租约和领取标记避免旧处理者清理新任务。写入后、确认完成前崩溃也可安全重复执行。

补写只操作使用记录，不再执行扣款。如果数据库中存在零实际费用占位行，可按已提交的快照、严格身份和金额校验恢复；不一致的非零费用记录不会被覆盖。损坏快照和冲突任务保留待排查。

旧版本已经发生、且没有持久化快照的历史缺失记录，不能凭空自动重建。用量数据库长期不可写时，未完成补写任务仍会增长，不能按普通日志删除。

## 归档和磁盘

默认将超过90天的已结束预扣记录及相关已处理核对记录，在同一事务中移到 `balance_precharges_archive` / `balance_precharge_reviews_archive`。仍冻结、仍有有效租约、近期更新的核对记录不会被移动。复制或删除任一步出错会整批回滚。

历史视图和计费查找同时读取热表与归档表，归档后仍支持查询和重复请求保护。**归档减少热表负担，不限制整个 PostgreSQL 的财务数据总量**；去重证据也继续保留。

新增存储监测默认每5分钟检查应用与日志目录所在文件系统，以及当前 PostgreSQL 数据库大小。默认本地磁盘使用达到85%、可用空间低于2 GiB，或数据库达到20 GiB时记录告警。进入异常、恢复会记录一次；持续异常至多每小时提醒一次。告警通过现有应用/运维系统日志渠道呈现，不会自动删除财务记录或改变计费。

远端数据库宿主机的剩余磁盘无法通过应用目录检查得知，需要在数据库主机配置容量监控。数据库大小告警只是容量预算，并非数据库最大文件限制。

运行日志使用现有轮转：本地启动脚本写入 `backend/logs/sub2api.log`，单文件100 MiB、最多10个备份、保留7天并压缩；不再生成额外的无上限 stdout/stderr 文件。四份部署 Compose 的 Sub2API 容器日志设置为每文件50m、5个文件。既有历史文件和压测报告不会被本次改动自动删除。

## 只读诊断

以下查询不改变资金：

```sql
-- 未完成补写和最早一笔的时间
SELECT COUNT(*) AS pending, MIN(created_at) AS oldest,
       MAX(attempts) AS max_attempts
FROM usage_log_outbox;

-- 补写失败分类，避免读取可能包含用户信息的快照
SELECT last_error_code, COUNT(*)
FROM usage_log_outbox GROUP BY last_error_code;

-- 未完成冻结及所有者状态
SELECT id, user_id, amount, lease_expires_at, lease_ended_at
FROM balance_precharges WHERE state = 'reserved';

-- 当前数据库大小
SELECT pg_size_pretty(pg_database_size(current_database()));
```

出现持续积压时先处理数据库可写性、容量、权限或使用记录冲突，再等待任务重试。不要清空去重、冻结或补写表来消除告警。维护工作不依赖普通文本日志，因此压缩运行日志不会改变费用或造成重复扣款。

固定预扣依旧按已选定规则工作：实际费用超出预扣时继续补扣差额。因此本功能限制低余额并发的资金占用，但**不承诺实际费用超出可用资金时余额绝不为负**。
