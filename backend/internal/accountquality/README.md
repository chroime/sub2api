# 账号质量监测

管理员入口为“智能运维 → 账号质量”，账号管理还提供可选的质量监测列和批量绑定、重测入口。与现有本地分组检测不同，每个样本只允许由绑定的账号执行，使用该账号的凭据、代理、模型映射和真实并发槽；不会由其他账号接替执行。

绑定账号时可搜索选择策略和账号，账号选项展示名称、ID、平台、类型与状态，并按策略平台过滤。账号管理的单行“更多 → 绑定／更换质量策略”会预选该账号；批量、分组和平台绑定仍可使用。无法读取或平台不兼容的选择会阻止提交，服务端在绑定事务中再次校验。

账号行内使用控制区与最近结果区的紧凑布局：左侧显示状态、人工复核入口和自动隔离开关，右侧显示最新结论、耗时、实际回答摘要及最多 30 次的单行样本条。摘要按实际时间排序，预览只读取模型输出末尾最多 240 个 Unicode 字符，不把参考答案当成真实回答；完整题目、回答和配置继续从证据详情读取。小容器中两区上下排列，样本条保持单行。

行内人工复核和自动隔离开关只打开指定账号、指定绑定的操作表单，填写原因并提交后才写入。绑定在刷新期间消失时停止操作，不会把原来的动作或原因自动套用到另一个绑定。人工复核追加操作审计，保留原始自动结论。

新策略默认暂停、仅记录与通知。绑定账号时自动隔离默认关闭；邮件和 QQ 通知也独立默认关闭。开启自动管控需要同时选择自动隔离策略、开启账号绑定上的自动隔离，并使用支持该能力的适配器。只读取页面或打开详情不会产生探测请求。

默认每 600 秒巡检。首次明确不合格后 60 秒复核，连续两次明确不合格才隔离。隔离冷却 900 秒后复测，随后每 300 秒复测；连续两次有效合格才解除本绑定拥有的质量门。超时、网络错误、429、鉴权失败、取消、输出截断、证据不足和预算暂停不会推进或清零能力计数。冷却到期本身不会解除隔离。

内置题目为带随机输入的确定性逻辑、精确指令和上下文检索；糖果题可选，仅自动检查唯一明确的数值结论。原题、回答、题目与适配器版本、策略快照、实际账号、请求/映射/返回模型、推理参数、Token、耗时和执行分类均保存在管理员证据中。人工确认误报只追加操作记录，不修改原始样本。

## 支持范围

已验证适配器包括 OpenAI API Key Responses/Chat Completions、Anthropic API Key/OAuth、原生 Gemini API Key/OAuth/服务账号、Grok API Key Responses/Chat Completions。具体可选组合由 capabilities 返回。

OpenAI OAuth/setup-token Responses 可执行观测探针，明确使用本地输出字节上限及超时；已完成且未截断的确定性答案可参与自动质量管控，传输异常和截断结果不会自动隔离。其上游不支持统一输出 Token 上限，因此配置全局金额预算时会暂停这种探针，不将该上限视为可信消费预留。影子账号、Agent Identity 及尚未验证的协议会明确返回 unsupported。

请求预算包括同一账号在不同策略下的诊断请求。金额预算按实际映射模型的单价保守预留，记录返回的 Token 消耗；价格未知或输出上限不可验证时暂停。诊断流量不扣客户余额，不写入客户业务使用记录。

## 隔离与并发

权威状态与证据保存在独立 PostgreSQL 表。账号上的 `extra.account_quality_gates` 仅为调度投影，按绑定 ID 分别持有；普通账号编辑、导入、复制、批量更新和连通测试恢复不会修改它。状态及调度 outbox 在同一事务提交，并立即刷新单账号快照。

质量门与人工 schedulable、鉴权、额度、限流等限制共同生效。探针只在内部移除自身绑定的质量门，保留其他限制。管理员手动检测还允许在业务调度暂停时执行，仅修改本次诊断的内存副本，不开启账号的业务调度；定时检测继续遵守暂停状态。账号禁用、错误、过期、冷却、额度、限流、其他绑定的质量门和真实并发限制仍然有效。管理员临时放行有明确期限，只覆盖对应质量门；解除一个绑定不会解除其他绑定的隔离。

诊断沿用账号指定代理的实际网络路径，不会自动把系统代理作为前置代理。代理 TCP 建连、TLS 或响应读取超时且策略上下文仍有效时，证据记为执行异常 `network_timeout`；只有策略的实际截止时间到达才记为策略超时。这些执行异常均不作为模型能力不达标计数。判断代理可用性应从运行后端的同一台机器、同一条网络路径验证。

每账号只允许一个排队或执行中的检测，全局执行并发默认 2。持久化租约支持多实例与重启后的过期清理；取消运行中的检测时保留占位，等请求退出后才允许下次执行。策略、绑定、账号身份或实际模型变化后，旧结果仅保留证据，不作用于新状态。

邮件和 QQ 使用账号质量独立事件/收件人/目标设置，复用现有 SMTP 与已保存的 AstrBot 连接，不继承上游邮件或本地分组事件。通知入持久队列，单独重试；持续隔离或预算暂停按提醒间隔去重。通知发送不阻塞探针调度。

## 验证

单元测试覆盖状态机、固定账号适配器、参数、响应结束、截断、代理及并发释放、普通与粘性调度、快照和保留字段。管理端输入与默认关闭的外部通知也有独立回归。

PostgreSQL 集成测试需要显式设置 `ACCOUNT_QUALITY_TEST_CONFIG`，仅从指定的本机配置读取数据库连接。每例创建随机 `aq_test_<UUID>` schema，所有测试连接的 search_path 仅指向该 schema，创建合成账号并应用迁移 274，最后只删除该测试 schema。模型与通知传输均使用测试替身，不请求真实上游或真实收件人。

```powershell
go test -tags integration ./internal/accountquality -run '^TestQualityPostgres' -count=1 -timeout 180s
```
